2. 项目定位与解决的问题

给医药随访团队用的 回购预测看板。输入是常规业务报表，输出是"这周该催谁、为什么、催了没"。

它替人做掉的三件体力活：

  1. 算应购药日期 —— 从销售明细自动算出每个患者每个品种下次该买的日期，不用人工拿计算器按周期推。
  2. 匹配随访记录 —— 自动找到对应那次随访的原始内容（用药状态、停药原因、随访小结），不用在两张表之间来回 V 找。
  3. 判定状态 + 生成话术 —— 把患者分成「应回购（应回未回 / 应回已回）/ 已逾期 / 未到期」，并生成可直接复制到群里的整体小结。

额外能力：展示层脱敏（投屏、共享屏幕时一键隐去姓名电话）、脱敏快照（生成不含个人信息的只读网页外发）、随访回传（在看板里填的备注，下次分析自动接续）。

技术形态：单页 HTML + 纯前端。逻辑全在浏览器里跑，没有服务器，因此部署成本为零、也不存在数据外泄的服务端环节。

5. 核心计算口径（最重要）

这一节是看板的"心脏"。所有数字都从这几条规则来，排查问题时先回到这里。

5.1 第一步：得到每个患者×品种的购药记录

按 电话数字 聚合（无电话则按姓名），每个患者每个品种得到一串购药记录：

[{日期: 2026-08-01, 数量: 3}, {日期: 2026-08-20, 数量: 1}, ...]
  • 购药数量做容错解析：2盒 → 2、1.5 → 1.5、1,200 → 1200；

缺失、非数字、非正数一律按 1（等价于"不放大"，与历史行为一致）。

  • 同一天的多行数量相加（3 行各买 1 支 = 一次买了 3 支）。

5.2 第二步：算出「本次购药覆盖天数」

覆盖天数 = 购药数量 × 单次用药周期        （该品种勾选「按数量」时）
覆盖天数 = 单次用药周期                   （未勾选时，数量按 1 计）

「按数量」是每个品种一个开关，默认关闭。所以： 默认状态下，本功能不影响任何历史结果——想让哪个品种"一次买几个周期就按几个周期算"，把它的「按数量」勾上。

5.3 第三步：按所选「周期算法」推进「库存耗尽日」

三条记录按日期升序逐条推进，库存耗尽日 就是下次应购日：

剩余库存 = 上次库存耗尽日 - 本次购药日

重置式     base = 本次购药日
累计式     base = max(本次购药日, 上次库存耗尽日)
累计+容差  base = 剩余库存 ≤ 容差天数 ? 本次购药日 : 上次库存耗尽日

库存耗尽日 = base + 本次覆盖天数
算法语义什么时候用
重置式（默认）每次购药都从本次重新起算最直观、最好解释
累计式只要还有剩余库存就往后顺延患者习惯囤药
累计 + 容差剩余库存 > 容差算囤药（顺延）；≤ 容差算小幅提前（重新起算）兼顾两者，避免小幅提前累积导致预测日期长期漂移

容差天数默认 7 天，仅在「累计+容差」下可改。

关键性质：药已吃完才买（剩余库存为负）时，三种算法都自动走重置分支——不需要额外判断。

实例（周期 21 天）：8/1 买 3 个周期、8/20 再买 1 个周期

算法8/1 的覆盖8/20 的处理下次应购日
重置式—从 8/20 重新起算 21 天9/10
累计式覆盖到 10/3剩余 44 天 > 0，顺延 21 天10/24
累计+容差(7)覆盖到 10/3剩余 44 天 > 7 → 顺延10/24
累计+容差(60)覆盖到 10/3剩余 44 天 ≤ 60 → 重置9/10

5.4 「应购药日期」与「预判应购日」

  • 应购药日期 = 推进到全部购药记录后的库存耗尽日 = 下次应该买的日期
  • 预判应购日 = 推进到「除最后一次以外」记录的库存耗尽日 = 上一次本该买的日期

「预判应购日」用于对比实际购药是提前还是延后。仅当该患者该品种有 ≥2 条购药记录时才有值（只有 1 条时无参照，显示 —）。

5.5 随访匹配规则

  1. 先按电话数字找该患者的随访；找不到再按姓名。
  2. 优先取同品种的随访；同品种一条都没有时，用该患者的全部随访。
  3. 优先「真实执行过」的随访（有执行时间，或任务状态含「已完成」），避免未执行的空任务干扰。
  4. 在上一步的结果里，取应购药日期之前、最近的一次；若之前一条都没有，取之后最早的一条。
  5. 随访日期 = 执行时间 的日期部分，缺失时用 计划执行时间。

5.6 状态判定（周维度 · 购药事实优先）

时间窗口 = 所选周（上周 / 本周 / 下周，默认本周），其起止由「参考日」和「周截止日」共同决定（见 5.7）。

判定顺序（从上往下，命中即停）：

顺序条件结果
1所选周内有购药记录应回购 · 应回已回
2应购药日期 < 周首已逾期
3应购药日期 ≤ 周末应回购 · 应回未回
4其余未到期
  • 应回购（总集）= 应回未回 + 应回已回
  • 第 1 条最优先：只要当周有购药记录就算「已回」，包括提前囤药的情况
  • 应购药日期落在所选周的行会置顶显示 + 浅金色底色，导出 Excel 同步整行浅金底

5.7 时间口径：参考日 + 周截止日

  • 参考日：默认今天，可手动改为历史日期以回看当时的状态（回看历史周）。
  • 周截止日：定义"本周"在哪一天结束，默认周日（= 自然周 周一~周日）。
周截止日选择得到的"本周"
周日（自然周）周一 ~ 周日
周五上周六 ~ 本周五
周六周日 ~ 周六
周一 / 周二 / 周三 / 周四周二~周一 / 周三~周二 / …

算法：本周 = [截止日-6, 截止日]，截止日取「参考日当天或之后最近的该星期几」，因此本周必定包含参考日。上周 / 下周各平移 7 天。

6. 界面操作手册

页面从上到下分五区：

6.1 上传区

  • 整条可点击选文件，也可拖拽；支持一次多选。
  • 每个文件会显示自动识别出的类型（销售 / 随访 / 周期 / 未识别）。
  • 未识别的文件会在点「开始分析」时被拦下并列出文件名，移除后重试即可。
  • 分析完成后上传区仍保留，可增删文件后再次分析。
  • 顶部会显示：销售明细 N 条 · 随访任务 M 条 · 用药周期 K 人（若本轮有回传数据接续，会追加提示）。

控件作用

容差天数，仅在「累计+容差」下可改

6.3 筛选区

  • 状态卡片：应回购 / 未到期 / 已逾期（+ 应回购细分 chips）。点选即筛选；卡片计数会随其他筛选实时变化。
  • 未购药原因 chips：按原因分类筛选。
  • 多选下拉：品种 / 医院 / 药房 / 随访人（多选=或）。
  • 关键词搜索：匹配 患者 / 电话 / 医生 / 医院 / 药房 / 品种 / 随访人。
  • 清空全部：回到默认状态（本周 + 今天）。
  • 所有筛选条件叠加生效（交集）。

8. 随访回传闭环

解决的问题：在看板里填的跟进备注、点选的未购药原因，原本关掉页面就没了，下一轮又要重填。

用法（两步）

  1. 本轮工作完成后，点「导出随访回传表」→ 得到 随访回传_日期.xlsx。
  2. 下一轮上传数据时，把这个文件连同销售/随访/周期表一起拖进去 → 系统自动接续。

接续效果

回传内容下一轮的表现
跟进备注回到「跟进备注」列，仍可继续编辑
未购药原因等同人工点选（优先于文本自动判定）

顶部会提示「已接续回传 N 条备注 / M 条原因」。已在本轮改过的内容不会被导入覆盖。

回传表结构（如需手工造表，照此列名）

列名内容说明
任务状态固定 已完成识别签名，缺了会认不出
服务摘要固定 跟进回传识别签名 + 回流标记
患者姓名明文匹配键
联系电话明文匹配键（优先）
产品品种用于同品种优先匹配
执行时间导出当天决定匹配到哪一周
执行人随访人
未购药原因中文标签（如 脱落·经济）导入后等同人工点选

随访小结原随访小结保留原记录

为什么必须明文：随访记录靠电话或姓名匹配到患者，脱敏后（张*三 / 138****1111）匹配不上。因此回传表强制明文，且含明文姓名与电话，只能在团队内部流转。

导出范围：只导出「有填写」的行（填了跟进备注 或 点选过未购药原因），避免把整张名单变成随访记录污染随访池。

14. 排错 FAQ

Q：上传后提示「未识别」怎么办？ 逐个检查该文件的表头是否含足够的关键字：销售表需含 销售时间 + 会员姓名；随访表需含 任务状态 + 服务摘要。缺了就往 mapping.js 的 TABLE_SIGNATURES / KEYWORD_RULES 里补关键词。

Q：列表是空的 / 一个人都没有？ 先看顶部 销售明细 N 条。N=0 说明销售表没被识别（表头问题）。N>0 但列表空，通常是筛选条件叠加太严——点「清空全部」重来。

Q：某患者的状态看起来不对（明明买了却显示逾期）？ 按顺序查：

  1. 该患者的电话在销售表和随访表里是否一致（电话不一致会退化成按姓名匹配）；
  2. 周期取值是否正确（周期表 / 品种标准周期）；
  3. 「按数量」是否该品种勾上了而购药数量列是空的；
  4. 周期算法是否与预期一致（重置 vs 累计会差出很多天）；
  5. 参考日 / 周截止日是否被改过。

Q：改了代码但页面没变化？ 忘了跑 python build.py。index.html 是产物，直接改源码不生效。

Q：导出的 Excel 列不对 / 少了列？ 先检查「表头显隐」是否隐藏了列——导出跟随当前可见列（「仅会员号」模式下电话列也会被去掉）。

Q：push 报连接 github.com 失败？ 本机对 github.com:443 存在间歇性不通（但 api.github.com 与 Pages 站点正常）。不要放弃，间隔 15 秒重试 8~10 次通常就能成功。

Q：git revert / checkout 之后文件莫名消失？ 本机有文件删除拦截层，曾在 git revert 后误删整个 tests/ 目录。这类 git 操作后务必 ls 关键目录；若真丢了，git restore --worktree <目录>/ 可全部找回（内容在 git 里没丢）。
