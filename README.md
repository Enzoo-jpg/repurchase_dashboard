# 预计购药分析看板（网页共享版）

针对 **诺倍戈（达罗他胺） / 博瑞纳（洛拉替尼）** 两个品种的患者，融合 **销售明细 + 随访任务 + 患者用药周期** 三张表，
在浏览器内自动计算「应购药日期」，匹配距离应购药日期最近一次的随访记录，
综合判定患者状态，并按 **品种 / 随访人 / 医院 / 状态 / 应购日期范围** 多维筛选。
支持 **脱敏 / 不脱敏两种网页快照** 与 Excel 名单导出，可直接离线打开或外发分享。

- 纯前端、无后端、无网络请求：数据从不离开本机。
- 归一化逻辑复用自 `followup_dashboard/webapp`（关键字启发式列映射，**表头变化也能兼容**）。
- **统一上传 + 自动识别**：一次拖入/选择多张表，按表头自动识别类型；已选文件列表可确认/删除，
  开始分析后上传窗口仍保留，可增删后再次分析。
- 姓名 / 电话 / 医生支持**展示层脱敏切换**，导出与快照亦有独立脱敏选项；患者姓名脱敏方式四选：**保留首字 / 保留首+末字 / 仅会员号（患者列显示会员号，医生列隐藏）/ 全部隐藏**（销售表需含「会员号」列）。
- 表格末列支持**手动填写跟进备注**（仅「应回购 / 已逾期」两类显示填写窗口），内容随快照一并保存。
- 适合「团队共用 + 外部脱敏网页快照分享」场景。

## 数据需求（三张表）

| 表 | 关键列（关键字自动识别） | 说明 |
|---|---|---|
| 销售明细（必需） | 销售时间 / 商品名称 / 会员姓名 / 会员电话 / 医疗单位 / 药房名称 / 处方医生 / 适应症 | 每行一次购药；应购药日期由此计算；医生列取自「处方医生」 |
| 随访任务（可选） | 任务状态 / 患者(患者姓名) / 联系电话(电话号码) / 计划执行时间(计划执行日期) / 执行时间 / 产品(药品名称) / 服务摘要(任务摘要·任务类型) / 执行人 / 随访小结(患者反馈内容·备注) | 多模板合并大表亦可；**新旧版表头措辞自动兼容**（括号内为「历史任务」类导出用词）。信号列亦双兼容：「患者目前的用药状态 / 用药周期状态」「是否判定易脱落 / 是否脱落·是否确认脱落」「判断为易脱落的原因 / 脱落原因」「推迟用药的原因 / 未按计划持续用药原因」 |
| 患者用药周期表（可选） | 患者 / 用药周期（天） | 按患者覆盖周期；表中没有的患者用品种标准周期 |

> 用药周期优先级：**周期表 > 品种标准周期**。标准周期**只按上传数据中实际出现的品种生成**
> （不写死内置商品）：内置品种族用内置默认值（诺倍戈 30 天 / 博瑞纳 30 天），
> 出现的新品种默认 30 天；界面「判定配置」栏**只显示数据中出现的品种**并允许修改，
> 周期表未覆盖的患者使用对应品种标准周期。

## 核心计算口径

1. **应购药日期** = 该患者该品种最近一次购药日期 + 用药周期。
2. **随访匹配** = 取应购药日期 **之前最近一次** 随访（同品种优先；若之前没有，取之后最早一条；
   优先「已完成 / 有执行时间」的真实随访，避免未执行任务干扰）。
3. **状态判定**（周维度状态机）。时间基准 = **参考日期**（默认今天，可手动改以回看历史周）所在**自然周（周一~周日）**；视图可选 **上周 / 本周 / 下周**（单选，默认本周），所选周即状态判定的时间窗口：
   - 三个主状态：
     - **应回购**（所选周应购清单）= **应回未回 + 应回已回**：
       - **应回未回**：应购药日落在所选周内、当周未购药（该催的名单：上周=该买没买，本周=待催，下周=提前看）。
       - **应回已回**（**购药事实最优先**）：**所选周内有购药记录**（本周该买也买了 / 提前买都算）。
           应购药日期列显示「预判应购日」（= 倒数第二次购药日 + 周期，≥2 条购药记录时），
           并标注 **提前 N 天 / 延后 N 天 / 按时**；仅 1 条购药记录（无预判基准）时该列显示 —。
     - **已逾期**：应购药日在所选周之前（且当周未购药）。
     - **未到期**：应购药日在所选周之后（且当周未购药）。
   - 一句话：**当周购药 = 应回已回；应购日落在所选周且未购 = 应回未回；两者合计 = 应回购**（周选择器下显示所选周的具体起止日期）。**名单中「应购药日期落在所选周」的患者置顶显示并带浅金色特殊底色，导出 Excel 同步整行浅金底**。
   - **应回购细分**：状态卡片下方「应回未回 / 应回已回」chips 可点选筛选；行内状态列同时标注主状态与细分。
   - **未购药原因标注（所有患者均可点选）**：「未购药原因」列点击展开分类选择（层级：父类 ▸ 子类），为患者标注未购药原因；**自动判定（随访文本）预填为初始值**，人工点选覆盖（快照保存）。
     无标注时按状态显示占位：应回已回 =「已购药」、未到期 =「—」、其余 =「未标」。原因列可筛选（状态卡片下方 chips）。
   - **原因分类可维护**：整体小结面板「管理分类」→ 增删改分类 / 加子类 / 恢复默认；**「未购药原因」列选项与小结文案同步跟随**。
4. **筛选**：状态分类 / 应回购细分 / 未购药原因 / 品种 / 医院 / 药房 / 随访人 / 关键词与周视图叠加生效（交集）；**状态卡片计数随 品种 / 医院 / 药房 / 随访人 / 关键词 筛选实时变化**（点击状态卡片本身不改变计数基数）；**整体小结统计范围跟随 医院 / 药房 筛选**（多选=或；品种由 chips 切换）；「重置筛选」回到默认「本周 + 今天」。
5. **跟进备注**：仅「应回购 / 已逾期」两类患者显示填写窗口（其余大类显示 —）。
6. **整体小结**（按品种分别总结，随数据自动生成，可复制）：
   - **统计「所选周」**：跟随顶部 上周/本周/下周 视图（周一~周日完整周，与状态机同一范围；点上周即总结上周）；不受周期控件（近7天/自定义遗留项）影响；品种可点选切换，各品种独立小结。
   - 内容：本周应回购 / 应回已回 / 应回未回人数；**未购药原因 = 患者明细「未购药原因」列标注的汇总**（统计范围 = 应回未回 + 已逾期；层级父类人数 = 子类之和；分类顺序/增减由「管理分类」维护）；下周预计复购 / 正常回购 / 推迟（附原因）。
   - 口径（与状态机完全一致）：应回购（总集）= 应回未回 + 应回已回；应回未回 = 下次应购日（最近购药 + 周期）∈ 本周且当周未购；应回已回 = 当周有购药记录（含提前购药者）。下周预计 = 下次应购日 ∈ 下周（下个自然周）的患者，按随访信号分正常/推迟，脱落不计入复购。

## 本地预览

```bash
cd repurchase_dashboard
python -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000
```

> 双击 `index.html` 也可用（file:// 协议）；快照生成不依赖网络。

## 部署到 GitHub Pages

1. 推送到仓库（默认分支 `main`，仓库根即 `repurchase_dashboard` 内容）。
2. 仓库 **Settings → Pages → Build and deployment → Source = Deploy from a branch**，
   选择 `main` 分支、目录 `/ (root)`，保存。
3. 访问 `https://<用户名>.github.io/repurchase_dashboard/`。

## 快照（导出）功能说明

- **脱敏快照**：姓名、电话、医生已脱敏，文件中不含明文个人信息，可安全外发。
- **不脱敏快照**：含明文个人信息，仅可分享给可信接收方（生成前有隐私风险提示）。
- 快照为单文件 HTML，离线双击即可打开，只读展示当前筛选后的名单。
- **手动填写的「跟进备注」与「下钻状态手动修正」会随快照一并保存**，打开快照仍可见。
- **Excel 导出（带样式）**：表头加粗 + 品牌色底，状态列按大类着色（应回购红/已逾期橙/未到期蓝），应回购细分（应回未回红/应回已回绿）、
  下钻列按子状态着色、逾期「距今天数」标红加粗；分脱敏 / 未脱敏两种，含医生列、下钻子状态列与跟进备注列。
  导出基于 exceljs（`vendor/exceljs.min.js`），仍为纯前端、数据不出本机。

## 展示层脱敏与列显隐

- 筛选区下方提供 **姓名 / 电话 / 医生** 三组「脱敏 ⇄ 不脱敏」切换，实时影响表格展示（不改变导出/快照的独立选项）。
- **姓名脱敏方式可切换**：`首尾保留`（张*三 / 欧**德，默认）、`首字保留`（张** / 欧***）、`全部隐藏`（***）；
  展示层、**导出脱敏名单、脱敏快照均与所选方式保持一致**；替换几个字符就有几个 *。
- **表头显隐**：点「表头显隐」可勾选隐藏/显示任意列（含手动备注列）。
- 展开行小卡仅展示**随访信息 + 跟进备注**（医院/药房/医生等业务字段已在主表展示，不重复）。

## 维护（重要）

逻辑代码在三个源文件中，修改后**必须重新生成** `index.html`：

- `mapping.js` —— 三表字段映射 / 品种归一化 / 随访修正信号规则 / 状态分类
- `pipeline.js` —— Excel 解析 / 归一化（销售 / 随访 / 周期三表）/ 脱敏（姓名/电话/医生）
- `app.js` —— 合并计算 / 状态判定 / 筛选 / 渲染 / 手动备注 / 快照

```bash
cd repurchase_dashboard
python build.py      # 读取 index.template.html + 三个 js，生成部署用单文件 index.html
```

> `index.html` 是**由 `build.py` 生成的部署产物**，请勿手动直接改它；
> 改 HTML/CSS 请改 `index.template.html`，改逻辑请改上面三个 js，然后重跑 `build.py`。
